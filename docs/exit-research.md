# Offline-сравнение выходов

`cmd/research-exits` сравнивает выходы на **одинаковых входах, объёмах и исходном
риске**, не подключается к OKX/БД и не читает ключи. Старый `cmd/research` и
реальная торговля не изменены. Это не портфельный backtest и не доказательство
доходности: ограничения капитала, маржи, ликвидации и конкуренция сигналов не моделируются.

## Запуск

Из корня репозитория, с Go 1.27 по `go.mod`:

```sh
go run ./cmd/research-exits -example
go run ./cmd/research-exits -input internal/research/testdata/exits-v1.json -stress=true
go test ./internal/research ./cmd/research-exits -count=1
```

Приложенный файл — **синтетический**, его результаты нельзя использовать для
выбора стратегии. `-example` показывает полный обязательный JSON-контракт.
При ошибке CLI возвращает nonzero без частичного успешного JSON. Допускаются
только локальные обычные файлы не больше 128 MiB. JSON с неизвестными или
пропущенными обязательными полями отклоняется; неизвестная комиссия не равна нулю.

## Формат и допущения

Отдельный `schema=1`, manifest `exit-policies-v1`. Он не совместим с Dataset
старого research. Типы и JSON-поля — `internal/research/exit_types.go`.
Каждый sample содержит анонимный ID, инструмент, `long`/`short`, точное время
и фактическую цену входа, начальные SL/TP, размер, ctVal/tick/lot/min, signed
entry_fee и fee_currency, явный snapshot Config, EndAt, свечи и funding.
Только линейные USDT-SWAP; account/order IDs, ключи и текущие настройки не нужны.

Config должен совпадать с явно выбранным manifest. Это фиксированное исследование,
не тихая подмена исторических правил. EndAt — общий горизонт доступных данных
для вариантов одной сделки, а не её исторический выход. Надо предоставить
непрерывные свечи до горизонта, в том числе после фактического закрытия.

Для входа внутри минуты обязателен `entry_tail`: OHLC **только после входа**,
от точного EntryAt до следующей минутной границы, с provenance/Source из более
детальных данных. Полная минутная свеча не годится. Валидатор проверяет геометрию
и покрытие, но не может доказать правдивость заявленного источника или `verified`:
независимая сверка исходных данных остаётся обязательной.

Основные бары — закрытые 1m, Start/End в RFC3339. Funding — исторические
`at/symbol/rate/mark`, не фактическая сумма всей позиции. `funding_complete=false`
и `spread_bps=null` означают неполные данные; во втором случае используется
явный `assumed_spread_bps`. Такие расчёты помечаются sensitivity-only.

## Профили

- `fixed_v1`: исходные SL/TP и фиксированный таймер; это контроль, не live-baseline.
- `configured_trailing_v1`: фиксированный TP, partial/BE/LOCK/time/stale из Config.
  Общий callback V3 для partial не воспроизводится; это не точная копия production.
- `runner_3r_v1`: без полного фиксированного TP с начала; до +3R — те же правила,
  после +3R — однократный partial и SL на расстоянии исходного1R от закрытия1m.
  Time/stale после активации отключены. Стоп никогда не ослабляется.

Числа example (BE1R, partial50% на1,25R и т.д.) — исходные предположения исследования,
не изменение реальной торговли и не доказанные оптимальные настройки.

## Исполнение и учёт

Решение принимается по закрытой свече, исполняется не раньше следующего открытия.
Старый SL имеет приоритет перед ожидающим market partial, если рынок уже прошёл
его на открытии. Новый SL не может сработать на low/high предыдущей свечи.
Если SL и TP затронуты в одной свече, выбирается SL-first и выдаётся предупреждение.
Гэп через SL ухудшает цену; защитный intrabar-выход датируется концом свечи,
что явно отмечено как модельное допущение. Невозможный после гэпа partial-SL
не устанавливается: прежняя защита сохраняется, появляется предупреждение.

Partial округляется вниз; минимальный размер остатка не нарушается. Если partial
невозможен, SL продолжает сопровождаться. Funding на границе времени начисляется
на размер, удержанный непосредственно до границы; на timestamp входа — нет.
При неизвестном порядке intrabar funding и SL/TP используется размер до выхода
с предупреждением `intrabar_funding_ambiguous`, это не точный биржевой итог.

Ledger хранит entry/partial/exit/funding/stop_move. Net = gross + signed fees
+ funding. Rebates положительные; entry fee списывается один раз. NetR делится
на **исходный денежный риск** (distance × contracts × ctVal), не на маржу.
В stress удваиваются отрицательные комиссии и slippage, но не rebate, funding,
spread и не фактическая цена уже состоявшегося входа.

Незавершённые позиции — `censored`, без фиктивного закрытия в конце периода.
Их Net — уже реализованный ledger; `mark_to_market` остатка отдельно, без
гипотетической комиссии выхода. `remaining_risk` — расстояние от последнего mark
до текущего SL на остатке, не прогноз убытка с учётом гэпов.

## Чтение отчёта

В отчёте исходный SHA-256, версия модели, git revision (либо честное `unknown`),
manifest, exclusions, все outcomes с ledger, предупреждения и cohorts.
Для base и x2 отдельные cohorts: пересечение ID, закрывшихся во **всех трёх**
профилях. Вне этого пересечения outcomes не скрываются, но в сводку не входят.
Этот отбор сам может смещать сравнение; всегда смотреть долю censored и покрытие.
`no_common_closed_samples` означает отсутствие статистики, а не нулевую прибыль.

Paired deltas = runner минус `against` для того же sample. PF=null при отсутствии
убытков. Top1/Top3 — доля крупнейших положительных net в сумме положительных net;
null, если выигрышей нет. Результаты с неполными расходами/неоднозначным порядком
событий не дают оснований переносить параметры в live.

Основные исключения: `reconciliation_not_verified`, `unsupported_fee_currency`,
`config_snapshot_mismatch`, `intraminute_entry_coverage_missing`, `insufficient_coverage`.
Дубликаты, внутренние пропуски, неверная геометрия и числовое переполнение — ошибки,
а не автоматическое заполнение. Несогласованная AVAX из аудита1 октября не должна
получать статус verified только ради включения в результат.
