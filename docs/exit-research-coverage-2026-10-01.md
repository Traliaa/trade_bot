# Покрытие данных для сравнения выходов — 1 октября 2026

Итог: движок проверен на синтетических данных, но **проверенного реального
датасета для запуска пока нет**. Рыночные результаты трёх профилей не получены;
утверждать, что новый выход улучшил прибыль, нельзя.

Это проверка доступных артефактов и схемы хранения, а не повторный запрос
текущего счёта. Источник исторических чисел — [сверка 1 октября](strategy-audit-2026-10-01.md).
В том срезе было 43 закрытые записи с 12 сентября; одна AVAX не согласуется
с полным биржевым циклом, остальные 42 — кандидаты, **не автоматически verified**.

| Данные | Источник / что доступно | Пробел и влияние |
|---|---|---|
| Время, цена и исходный размер входа | `trade_history.payload`, `trade_fills`; для AVAX дополнительно проверен архив OKX | Для каждого кандидата нужна сверка принадлежности исполнений и объёма. AVAX исключается как mismatch; сведения аккаунта не подставляются вместо отдельного сигнала. |
| Исходный SL/TP и 1R | `TradePayload.StopLoss`, `TakeProfit`, `RiskDist`, отдельно `CurrentStopLoss` | Само наличие полей не доказывает исходные уровни. Нужны проверка сохранности и геометрии на момент входа; текущий подтянутый SL не заменяет исходный риск. |
| Снимок правил | `TradeConfigSnapshot` хранит BE/LOCK/partial/time и `StaleAfterBars` | Полного набора stale-полей в snapshot нет. Их исторические значения необходимо подтвердить версией кода/конфигурации. Текущие defaults не считаются доказательством. Несовпадение с manifest исключает запись. |
| Комиссия входа и валюта | `trade_fills.fee`; биржевые исполнения для независимой сверки | В `TradeFillRecord`/таблице нет валюты комиссии. Нельзя молча объявлять все комиссии USDT; для AVAX это уже проверено, для остальных требуется источник. |
| ctVal, tick, lot, min size | ctVal есть в payload; остальные параметры нужны из исторических метаданных инструмента | Сегодняшние ограничения не подтверждают исторические. Полного исследовательского snapshot в приложенном датасете нет. |
| Сегмент первой минуты после входа | Нужны сделки/тики или иной достоверный более подробный источник | Такого файла в репозитории нет. Для входов с секундами внутри минуты обычный OHLC не подходит: без сегмента запись исключается. Доля таких входов здесь заново не измерялась. |
| Последующие 1m до общего горизонта | Нужен локальный исторический набор свечей с происхождением | В новом testdata есть только synthetic fixture. Требуется непрерывная история, включая время после фактического выхода; отсутствующий хвост нельзя закрыть фиктивной сделкой. |
| Funding rate и mark | Исторические события ставки и mark в момент начисления | Сумма реального funding AVAX сверена, но она не заменяет события для альтернативных размеров/выходов. Для других кандидатов funding не сверялся; неполнота допускается только с sensitivity-only. |
| Спред / проскальзывание | Нужны исторические котировки либо явно зафиксированная модель | Историческая серия не приложена. В примере используются условные расходы; stress x2 — проверка чувствительности, не измеренный тариф/спред. |

Проверенные кодовые источники: `internal/models/trade.go`,
`migrations/0003_add_trade_history.sql`, `migrations/0004_add_trade_fills.sql`.
Они показывают структуру хранения, но не подтверждают качество каждой записи.

## Следующий этап данных

1. Подготовить обезличенную сверку кандидатов: исполнения, объём, комиссия и
   валюта, исходный риск, полный исторический snapshot правил/метаданных.
2. Проверить доступность сегментов после входа и 1m до заранее выбранного общего
   горизонта; фиксировать доступность по каждой записи, не округлять EntryAt.
3. Добавить funding rate/mark и явно выбранные расходы. Недоступные источники
   оставить видимыми, не заполнять нулями как будто они известны.
4. Зафиксировать нетронутый период, manifest и SHA входного файла; выполнить
   три профиля с base/x2 costs и опубликовать coverage/exclusions/censored рядом
   с парным результатом. Если пригодных записей нет, результатом остаётся
   отчёт о покрытии, а не выбор «прибыльной» стратегии.

Новый сбор tick-истории, загрузка архивов в production, исправление учёта AVAX,
изменение входов/списка монет и перенос правил в live сюда не входят.
