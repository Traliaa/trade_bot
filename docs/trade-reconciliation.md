# Сверка отчётности по сохранённым исполнениям

Существующий авторизованный `GET /api/stats` возвращает дополнительный объект
`stats.reconciliation`. Старые поля статистики сохраняются. Отчёт не обновляет
историю, не запрашивает биржу и не меняет торговые настройки.

## Границы доказательства

- `scope: stored_fills`: проверяется согласованность истории с записями `trade_fills`,
  а не полнота биржевого счёта. Валюта комиссии в существующей таблице не хранится;
  сверка использует записанные суммы в принятой системой единице учёта.
- `funding_status: not_checked`: funding не загружается и не считается нулевым.
- `checked_at`: время снимка базы, на котором выполнена сверка, **не время последнего
  получения данных от OKX**. Для каждой сделки возвращается `last_fill_at`, если есть
  валидные исполнения. Свежесть биржевого потока этим отчётом не подтверждается.
- Открытые позиции учитываются в прежних `open_trades`/`open_pnl`, но не включаются
  в сверенную статистику закрытых сделок.

## Статусы и результат

В `trades` каждая закрытая сделка имеет `trade_guid`, `inst_id`, `status`, `issues`,
суммарные объёмы входа/выхода и суммы комиссий, gross и net P&L сохранённых исполнений.

- `verified` — объёмы полные; комиссии, gross и net согласованы с историей в пределах
  допуска. Это **сверено по сохранённым исполнениям**, а не «подтверждено биржей».
- `incomplete` — отсутствуют исполнения входа/выхода или часть необходимого объёма.
  Денежные суммы неполной группы не сравниваются с итогом как будто группа полная.
- `mismatch` — дубликат, неправильная принадлежность/сторона исполнения, лишний объём,
  некорректные числа или расхождение денег. Этот статус имеет приоритет над неполнотой.

`issues` содержит стабильные коды: `missing_fills`, `missing_entry_fills`,
`missing_exit_fills`, `entry_size_shortfall`, `exit_size_shortfall`,
`entry_size_excess`, `exit_size_excess`, `history_size_mismatch`, `duplicate_fill`,
`fill_identity_mismatch`, `invalid_fill`, `invalid_history`, `numeric_overflow`,
`fee_mismatch`, `gross_pnl_mismatch`, `net_pnl_mismatch`. Проверка незакрытой записи
возвращает `trade_not_closed`; обычная статистика не отправляет такие записи на сверку.

Допуск сравнения: `absolute + 1e-9 × max(abs(a), abs(b))`; абсолютный допуск объёма
`1e-9`, денежных сумм `1e-5`. Это допуск численного сравнения, не округление ордера
до минимального биржевого лота. Положительная комиссия считается rebate, знак сохраняется.

`verified_stats` содержит только сверенные сделки: количество, wins/losses/breakeven,
win rate, net P&L, комиссии, средний P&L, profit factor. Суммы берутся из исполнений.
Funding не включён. При отсутствии убыточных сделок profit factor равен `null`,
а не нулю или бесконечности. Старые R/MFE/MAE не объявляются сверенными.

`verified_stats_status`: `available`, `no_verified_trades` или `numeric_overflow`.
При переполнении агрегатов `verified_stats` равен `null`: недоступная сумма не
выдаётся за нулевой результат. Статусы отдельных сделок при этом сохраняются.

## Загрузка и ошибки

История, исполнения и открытые позиции читаются одним SELECT со снимком PostgreSQL
и ограничением по авторизованному user ID. Параметр клиента `user_id` не выбирает
аккаунт. Один сетевой запрос вместо отдельного чтения исполнений каждой сделки;
для соединения есть индекс по `trade_guid`. Порядок закрытых сделок —
по времени выхода от новых к старым, как в прежних окнах статистики.

Ошибка загрузки/декодирования возвращает ошибку отчёта, не «0 сделок». Ответ
`Cache-Control: no-store` запрещает кеширование персональной сверки. Миграции
не добавляются: используются существующие таблицы 0003/0004. История не переписывается.

Числа исполнений читаются типизированными колонками PostgreSQL, без преобразования
в JSON на стороне базы. Сохранённый NaN/Infinity в исполнении даёт `mismatch`
конкретной сделки и не блокирует остальные записи отчёта.

## Проверки

Числовые тесты: частичные закрытия, rebates, short, допуски, отсутствующие и лишние
исполнения, дубликаты, принадлежность, неверные числа, расхождения комиссий/P&L;
агрегаты исключают неполные и противоречивые сделки. HTTP-тесты проверяют авторизацию,
выбор аккаунта из сессии, запрет кеширования и отказ при ошибке источника.

Интеграционный тест `TestReconciliationPostgresSnapshot` использует реальные миграции
0003/0004 и только отдельную локальную базу `trade_report_test`. Включается переменной
`TRADE_REPORT_TEST_DSN` с адресом `127.0.0.1`. Без неё пропускается. Никогда не указывать
production DSN. Тест проверяет также изоляцию пользователей и отсутствие изменений истории.

## Что пока не входит

Отдельный экран сверки во фронтенде, загрузка funding, независимая сверка с OKX,
исторический журнал сигналов, версии эффективных настроек и сравнение сопровождения
стратегии остаются следующими блоками. Эта поставка добавляет расчёт и API отчёта.
