## Причина в текущем коде

1. `sessions/resolve_closed_trade.go: resolveClosedTradeExecution` использует
   `RecentFills(..., 100)`, но не объединяет результат с `Repo.ListTradeFills`.
2. `okx_client/service/client.go: RecentFills` обращается к
   `/api/v5/trade/fills`, а не к архиву с пагинацией.
3. `closedTradeInput` заменяет gross суммой найденных выходов и добавляет
   комиссии этих выходов к payload. Для AVAX текущий итог воспроизводится
   из одного последнего выхода; раннее исполнение не участвует.
4. Проверка `exitSize <= EntrySize` относится только к полученной выборке,
   а не к объединённому журналу. Поэтому финальное закрытие 1 проходит,
   хотя сохранённые выходы уже суммарно составляют 1,5.

Потеря раннего P&L в финализации подтверждена данными и путём кода.
Почему исходная позиция 14 сентября отсутствует в учёте бота и почему не
сохранён второй частичный выход — пока не установлено. Текущий код не доказывает,
какая его версия обрабатывала события 14–18 сентября.

AVAX исключается из основной выборки подбора параметров по признаку
несогласованного учёта, **не из-за величины прибыли**. В отдельном отчёте
концентрации результата сохраняются обе суммы с разными областями учёта.

## Дальнейшая безопасная работа

- Отдельная задача: финализация по полному, дедуплицированному журналу с
  проверкой принадлежности, объёмов и комиссий; архивная дозагрузка по необходимости.
- Для общей позиции с несколькими источниками входа нужна явная модель атрибуции;
  нельзя автоматически присвоить весь её P&L последнему сигналу.
- Не переписывать production-историю и не импортировать архив до отдельного
  согласования правил атрибуции. Сначала тесты на обезличенных примерах.
- В первой версии исследования выходов принимать только входы с проверенным
  объёмом, исходным SL и документированной полнотой расходов/рыночных данных.

Контракты API: [OKX fills history](https://www.okx.com/docs-v5/en/#order-book-trading-trade-get-transaction-details-last-3-months),
[OKX positions history](https://www.okx.com/docs-v5/en/#trading-account-rest-api-get-positions-history).
